# S13: Sponsor integration map (all ten partners, plus PayPal)

Re-evaluated for code milestones on 5 October 2026. The original all-partners direction remains a goal, not proof of integration. Only the guarded funded-hold PayPal SDK adapter is implemented/tested locally; real sandbox qualification is still pending. All other runtime integrations below are planned.

## The map

| Partner | Planned code-milestone job | Boundary / fit |
|---|---|---|
| PayPal | Authorise/capture/void, Vault approval, provider reconciliation | Deterministic adapter only; models never receive credentials |
| APIMatic | Ground pinned SDK calls, generate Stood SDK/docs/MCP from OpenAPI | OpenAPI generation and MCP access remain pending; no second spec |
| AG Grid / AG Studio | Reviewer file and operation/reconciliation rows | Assistant reads/filter/sorts; no money permission; check commercial licence |
| Bryntum | Milestone Gantt, hold deadline, predecessor locks | Explain failed code condition; matching/hiring remain outside Stood |
| Render | Container API/worker hosting and durable timers | Untrusted runner requires separate qualified isolation; a normal app container is insufficient |
| Channel3 | Optional installed-fitting comparison in EyeOnSite scenario | Weak fit for code; no code-payment dependency or price-based refusal |
| Astropods | Credential-free advisory evidence/reviewer agent | Not a substitute for a qualified untrusted-code sandbox |
| Elastic | Searchable commit/report/decision provenance and field photo novelty | Tenant isolation; not authoritative payment state |
| Kernel | Automate sandbox buyer approval and record replay | Sandbox accounts only; no claim of approval today |
| Postman | Public API fixtures and qualification collection | Synthetic examples and real provider calls clearly separated |
| Zapier | Recipient sentence and reviewer alert delivery | Outbound only; cannot call release endpoints |
