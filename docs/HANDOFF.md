# Credential handoff: key inventory and deferred tests

**Status (2026-10-06):** everything below runs today against simulators and fakes, and the mock network suite is green. Nothing here has been qualified against a live provider. This page lists:

1. every credential the product will need, with its minimum scope
2. where each credential goes
3. every test that can only run once the credential exists

**Rules for every key:**

- Sandbox or test only. Never a live PayPal app.
- Enter values in the owner's own secret store (Render environment, GitHub Actions secrets, or `scripts/dev setup` locally). Never paste them into chat, issues, commits or screenshots.
- Live mode refuses to start with a named error if a key is missing. It never falls back to a simulator ([ADR-0018](adr/0018-provider-modes-and-simulation.md)).

## 3. Switching a provider to live

1. Create the credential from the table above, with the minimum scope.
2. Enter it in the owner's own store (`scripts/dev setup` locally, or the prompted Render variable).
3. Set the provider mode (for example `PROVIDER_PAYPAL=live`, which still means the PayPal **sandbox**).
4. Start the service. `/health` must report the provider as `live` and ready. A missing key or failed readiness is a named startup error.
5. Run the deferred tests for that provider, and record their evidence in [`TASKS.md`](../TASKS.md) before relying on it.
